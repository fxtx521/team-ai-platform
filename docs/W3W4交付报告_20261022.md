## 主控加固（终审中发现并当场修掉）

**发现 1（安全，已修）**：W3 列表端点 store.list_tasks() 不按 user_id 过滤——任何员工 token 都能看到全员任务。修复：过滤下沉到存储层（list_tasks 增加 user_id 参数，路由传 session.user_id），并写专项 ad-hoc 双用户隔离测试：admin 建 2 任务、boss 建 1 任务，各自 token 拉列表分别只看到 2 和 1（USER-FILTER-PASS）。修后 W1/W3-executor 回归全绿。

**发现 2（体验，W5 做）**：服务端无 CORS 头、未托管 web/ 静态目录——浏览器跨域直连会被拦。同源托管方案留 W5（部署阶段一起做，属于部署形态问题不是代码缺陷）。

## 环境坑追记

- 冒烟里 curl POST 默认 Content-Type 不是 application/json，FastAPI 会 422——W2/W3 脚本都显式带了 -H，我的临时诊断脚本第一次没带导致 KeyError' 假阴性，加头后真阳性。以后所有 curl POST 必带 -H 'Content-Type: application/json'。
- 前台命令不许用 & 起服务——统一封装进临时脚本+trap 清理（本报告所有 ad-hoc 都这么跑的，跑完即删）。
